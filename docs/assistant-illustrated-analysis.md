# 国画助手图文赏析发布说明

图文赏析复用助手已有的附件、运行和 SSE 接口。`qwen3-vl-plus` 可在赏析正文中返回局部坐标，Web 按当前问题的附件顺序定位原画，并把局部和讲解并排显示。迁移后，Core 可在私有执行请求中提供补定位预算。Critic 只在本轮有图片、问题需要赏析且正文缺少可用坐标时，使用本轮图片和缺图段落进行至多一次补定位。

补定位沿用同一次助手运行，最多 8 秒，受现有总时限、空闲时限和取消控制约束。优先使用同一通道已配置的 `qwen3-vl-plus`，否则使用当前视觉模型。失败、缺少有效坐标或预算不足时保留主回答。补定位可能产生额外模型用量，Core 在同一运行的 `usage.illustration` 记录状态和供应商实际返回的 token 统计。部署沿用现有助手发布合同。

## 发布顺序

1. 按各仓库的正常流程合入 `main`，通过 `main` 到 `release` 的 PR 生成正式制品。发布前从助手模型注册表核对 `qwen3-vl-plus` 已配置、已启用并支持图片。使用当前环境的已批准配置和制品绑定。
2. 先发布 Core，再发布 Web。旧 Critic 忽略私有补定位预算请求头，继续返回原有事件。Web 发布后确认页面通过既有运行接口读取完成态正文，并正常恢复历史会话与附件。
3. 按 [R25 AI 发布流程](../r25/AI_RELEASE_CONTRACT.md) 发布 Critic。旧 Core 未提供预算请求头时，新 Critic 继续一次调用。新版 Core 与 Critic 配对后才会补定位。
4. 逐项核对下面的验收场景。旧坐标格式、已有历史、旧客户端请求和 JSON/CSV 导出均纳入回归。

## 验收

| 场景 | 预期行为 |
| --- | --- |
| 首轮已有有效坐标 | 只有一次上游调用，点击局部可打开本轮原图。 |
| 缺坐标、补定位成功 | 最多两次上游调用，同一个 Core 运行。最终正文带局部坐标，刷新后局部与原段落、附件一致。 |
| 补定位超时或坐标无效 | 主回答保存成功，文字可继续阅读。 |
| 文字追问、纯文字赏析、历史图片 | 沿用已有上下文规则，补定位只接受本轮图片。 |
| 语音与档案 | 语音默认进入草稿。分别试用自动发送和自动朗读。确认创作记录和 JSON 导出标明输入方式，手动文本和历史数据仍可读取。 |
| 纪要与选择卡 | 验证五段式中文纪要、原自动摘要限频和分支隔离。创作取舍可出现选择卡，选择后通过原选择接口继续。 |
| WebP 选择、粘贴、刷新 | 入库前转为 PNG，确认待发送草稿、私有图片、原图查看和配额检查走原接口。 |

服务启动后执行真实模型和麦克风验收。运行 R25 发布前核对四仓源提交与制品身份。

## 回退

先按 R25 AI 流程恢复 Critic，即可停用补定位和新提示词。再按需要回退 Web 和 Core。已保存的补定位正文使用原有 `assistant-crop` 坐标格式，当前 Web 和前一版图文赏析 Web 都能展示。创作输入方式保存在既有运行选项中，无需反向数据库迁移。
